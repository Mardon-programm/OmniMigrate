# OmniMigrate Service Level Agreement (SLA)

**Версия:** 1.0 · **Дата:** 2026-08-23 · **Статус:** Offered with Enterprise & Scale plans

## 1. Service Description

OmniMigrate — автономный движок миграции и модернизации кода: клонирует
репозиторий, анализирует AST, рефакторит через LLM-конвейер, верифицирует
в изолированной песочнице и открывает pull request.

Компоненты сервиса:

| Компонент | Описание |
|---|---|
| **API Gateway** | REST API (`/api`), аутентификация, авторизация, rate limiting |
| **Migration Workers** | Выполнение пайплайна parse → refactor → verify → PR |
| **Web Console** | Веб-интерфейс управления проектами и задачами |
| **Usage/Billing API** | Метрики потребления, лимиты планов |

## 2. Uptime Commitment

Uptime измеряется помесячно по endpoint'ам `/healthz` и `/readyz`,
проверкам каждые 60 секунд из двух независимых регионов.

| План | Monthly Uptime | Downtime / мес |
|---|---|---|
| Free | Best effort | — |
| Team | 99.5% | ≤ 3ч 39м |
| Business | 99.9% | ≤ 43м |
| Enterprise | 99.95% | ≤ 21м |

**Exclusions:** плановые обслуживания (уведомление ≥ 72ч, окно
Sun 02:00–06:00 UTC), отказы вышестоящих провайдеров (GitHub, Stripe, LLM),
форс-мажор, изменения внесённые клиентом.

## 3. Support Tiers & Response Times

Response time = первый содержательный ответ инженера. Resolution time —
целевые (non-binding) значения.

| Severity | Определение | Enterprise first response | Target resolution |
|---|---|---|---|
| **S1 Critical** | Прод недоступен, невозможна миграция/логин | 30 min, 24×7 | 4 ч workaround |
| **S2 High** | Деградация: падение % успешных миграций, задержки очередей > 15 мин | 2 ч, 24×7 | 1 рабочий день |
| **S3 Normal** | Некритичный дефект, вопросы интеграции | 8 ч, бизнес-часы | 3 рабочих дня |
| **S4 Low** | Косметика, feature requests | 2 рабочих дня | По роадмапу |

Каналы: S1/S2 — выделенный Slack Connect + hotline; S3/S4 — support portal.

## 4. Data Protection Commitments

- RPO ≤ 15 мин (WAL-архивирование Postgres), RTO ≤ 1 ч.
- Шифрование: TLS 1.2+ в транзите, AES-256 at rest (диск БД + Fernet для GitHub-токенов).
- Retention audit log ≥ 12 мес, job artifacts ≥ 90 дней (Enterprise: настраиваемо).
- Удаление данных организации — полное, в течение 30 дней после запроса; справка об удалении по запросу.

## 5. Migration Success SLA (Business/Enterprise)

Для задач с приоритетом `urgent`: старт обработки ≤ 5 минут после постановки
в очередь (p95). Целевой процент успешных миграций Python 3.7→3.12 при
прохождении тестов в легаси: ≥ 85% (измеряется по завершённым job за месяц).

## 6. Credits

При нарушении uptime-обязательств клиенту начисляется сервисный кредит:
0.5% от месячной платы за каждые 0.1% ниже порога, максимум 25%.
Кредит запрашивается в течение 30 дней через support portal.

## 7. Review

SLA пересматривается ежеквартально. Изменения публикуются за 30 дней,
не применяются ретроактивно.
